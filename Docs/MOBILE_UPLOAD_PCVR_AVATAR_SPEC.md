# Mobile publication to PCVR presentation

Deliver one account-owned head on the tracked Mimic body after the phone publishes,
without reinstalling the PC application. Do not depend on expired raw capture.

1. Workstation: verify the active published job still belongs to the authenticated
   account. Stage its GLB privately, validate input limits and finite geometry,
   normalize non-unit node rotations on a derived copy only. Keep face data,
   signed URLs, credentials and derived assets out of Git and logs.
2. Presentation gate: attach the imported head at the tracked head socket, hide
   the original visible head without breaking tracking, and check materials,
   orientation, neck and first-person clipping in the mirror. Transient PIE
   attachment was observed; visual acceptance and packaged rendering are pending.
3. Build a Win64 data-only Pak against the released engine/content baseline;
   include the approved mesh and material/texture dependencies, not scripts or
   animation logic. Publish only after a clean client can mount and load it.
   Record immutable avatar version, platform, client compatibility, byte size,
   SHA-256, scoped mount root and approved mesh reference.
4. Backend binds selection to the verified UID and active job. Replicate only
   approved avatar ID/version; clients resolve authorized delivery separately.
   Never accept client-provided mesh paths as server selection. Distinguish
   mobile published, PCVR processing, ready, and default in the menu.
5. Client downloads asynchronously to private storage, verifies size/hash and
   compatibility, rejects unexpected mount paths/content, then mounts and applies.
   Cancel stale work on account switch, deletion or a newer selection. On failure
   retain the default and allow a bounded explicit retry.

Acceptance: install first, publish from phone later, refresh and equip without
reinstalling. Verify reconnect/cache reuse, wrong-account rejection, corrupt and
incompatible payload fallback, deletion, and a second PCVR user's remote view.
Quest uses the native fallback until a separate Android cook passes. Do not use
another user's historical MetaHuman or claim the mobile GLB is a MetaHuman.
